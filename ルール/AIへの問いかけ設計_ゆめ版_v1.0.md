# AIへの問いかけ設計 ゆめ版 v1.0

きっかけ: あかりちゃんの有料記事「週末noteマン！時間がない人ほど、AIに任せる場所を探さない」（2026-07-31購入・読了）。
このファイルは記事の写しではなく、その考え方を水晶ゆめの体制に合わせて調律したもの。

## 記事の核心（ゆめの言葉で要約）

- 「自分の作業を分解して、一部をAIに渡す」だけだと、出てくるのは全部「自分の枠の中の最適解」
- 時間がない人は試行錯誤ができないから、枠が間違っていても気づけないまま速く走り続けてしまう
- だから時短の次は「同じ1回の質問で、返ってくるものの質を上げる」こと
- そのための条件が3つ: ①主語をAIにする ②制約を全部渡す ③失敗条件を先に書く
- 制約と型は1回作ればずっと使い回せる。つまり「思考のストック化」

## まず安心していいこと: ゆめの体制がすでにできていること

この記事に照らすと、ゆめのリポジトリ運用は条件②と③をすでに実装している。

- **制約のストック化（STEP2相当）**: CLAUDE.md＝人格・文体・倫理・note戦略を1回書いて全チャットで使い回す仕組みそのもの。記事の言う「制約を1回書けばコピペで使い回せる」を、コピペすら不要な形でやっている
- **失敗条件（STEP3相当）**: 「絶対に超えないライン」（読者を裏切らない・嘘を書かない・煽らない・切り売りしない）と、Layer 3の自問（読者を責めていないか・急がせていないか）は、そのまま失敗条件の集合になっている
- **判断を渡さないガード**: 「読者の今の感情の特定はAI任せにしない」ルールは、記事の「絶対やっちゃいけない使い方2（判断まで渡す）」の先取り

だから「うちは全然できてない」ではない。足りないのは1箇所だけ。

## 本当に足りていないもの: 「考えるAI」の席

ゆめのAI活用は、ほぼすべて「水晶ゆめの人格を着せた執筆代行」。
これは執筆には正しい（商品＝ゆめの声だから、枠の中で書くのが仕様）。

でも副作用がある。人格コアは「静けさ・やさしさ・無理しない」で調律されているから、
**この人格の中で戦略を聞くと、答えまでやさしく丸くなる**。
企画の方向転換や導線の欠陥指摘みたいな「痛いけど必要な視点」が出てきにくい。

そこで役割をふたつに分ける。

- **書くAI**: 人格コアの枠の中で書く（今まで通り。変更なし）
- **考えるAI**: 企画・点検・戦略のときだけ、枠の外から考えさせる（今回新設）

考えるAIへの依頼は「私はどうすればいい？」ではなく「あなたが渡されたら何をする？」の形にする。

## ゆめ版・質問の型3つ

### 型1｜立場交代型（企画・優先順位を決めるとき）

```
あなたが水晶ゆめのnoteを丸ごと渡されたとする。
現状: 朝活オラクル毎日／夜色アトリエ週1／Pollo AI案件／スレッズ1日4回／
メンバーシップ9名／パトレオン稼働中（＋その時点の実数を書く）。
使える時間は1日◯時間。
3ヶ月後に◯◯を達成しろと言われたら、何から手をつける？
やらないことも理由つきで挙げて。

失敗条件:
・無理なペースになって続かなくなること
・読者が「売り込まれた」と感じること
・静けさとやさしさの世界観が壊れること
```

### 型2｜前提破壊型（企画に詰まったとき・方針転換の前）

```
私はいま◯◯をしようとしている。
この問いの立て方、そもそも間違っていないか？
私が見落としている前提を3つ挙げて。
そのうえで、問い自体を立て直すとどうなる？
```

使いどころの目安: 同じ企画で2回以上まとめ直しが発生したら、3回目の前にこれを投げる。
（例: 自己紹介カード企画は診断→メーカーに転換するまで試行錯誤した。ああいう場面の短縮用）

### 型3｜人間不採算型（ストックが増えてきたとき）

```
人間なら手間が割に合わなくて絶対やらないけど、
AIならできることを、私の状況（保存版マガジン7本＋過去記事多数）で10個挙げて。
うち、1週間以内に始められるものを3つに絞って。
```

ゆめの場合の有力候補（すでに思いつく範囲）:
- 全過去記事の横断点検: タグが今の戦略（3〜5個・死にタグ排除）に合っているか棚卸し
- 全記事の末尾導線が「記事末尾導線テンプレ_v2」に揃っているかの確認
- 保存版マガジン同士の相互リンク漏れチェック
- パトレオンの英日バイリンガル投稿の表現ゆれ確認

### 導線点検（型1の変種・そのまま使える）

```
これが私の導線（無料記事→◯◯→メンバーシップ/有料）。
あなたが読者だったとして、どこで閉じる？
離脱しそうな場所を上から3つ、理由つきで。
失敗条件は、読者が「売り込まれた」と感じること。
```

## ゆめ版・失敗条件の定型（コピペ用）

記事の性質に合わせて選んで末尾に足す。全部は足さない（制約は具体的に、ただし軸は1つ）。

- 無理なペースになって続かなくなったら失敗（←時間がない人の最大の失敗。あかりちゃんの記事と共通）
- 読者が責められた・急かされたと感じたら失敗
- 静けさの世界観が壊れたら失敗
- 私が自分の言葉で説明できないものが混ざったら失敗
- 公開済み作品を有料の壁の中に入れたら失敗

## 変えないこと（このファイルで上書きしないガード)

- 執筆時の人格・文体・倫理は今まで通り人格コア＋記事執筆プロンプトに従う。このファイルは執筆には介入しない
- 「読者の今の感情」の特定は引き続きゆめが指定する（考えるAIにも渡さない）
- 値付け・公開可否・誰と組むかの最終判断はゆめ。AIが出すのは判断材料まで
- 考えるAIの出力も鵜呑みにしない。アルゴリズム情報と同じで、実際の数値・表示で検証する

## 起動の合図（実践での使い方）

- チャットで「考えるAIモードで」「問いかけ設計を使って」と言えば、AIはこのファイルを読み、人格の枠の外から考える
- ゆめが型を選ばなくてもいい。相談内容を伝えれば、AIがどの型（立場交代／前提破壊／人間不採算／導線点検）が合うか提案し、制約と失敗条件の穴埋めを一緒に確認してから投げる
- 出力を受け取ったあと、記事化などの実作業に移る時は、通常どおり人格コア＋記事執筆プロンプトに戻る（考えるAIの口調のまま記事を書かない）
