# dev/ — 開発用フォルダ

記事とは別に、**アプリ・ツールのコード**を育てる場所です。
書きかけ・動かないもの・実験中のものを、遠慮なく置いていい場所として作りました。

---

## このフォルダの考え方

| | 記事のファイル（リポジトリ直下） | dev/ の中 |
|---|---|---|
| 置くもの | 原稿・引き継ぎメモ・企画設計書 | アプリやツールのコード |
| 完成度 | 公開するもの／したもの | 途中でいい。壊れていていい |
| ブランチ | main（すべてのチャットが読む共有の記憶） | 開発ブランチ |

**大事なところ：** dev/ の中身は、開発ブランチで作業しているあいだ main には現れません。
main に入れたいものが出てきた時だけ、そのファイルを main に持っていきます（下の手順）。

---

## フォルダの中身

```
dev/
├── README.md   ← このファイル
├── apps/       ← アプリ開発。1つのアプリ＝1つのフォルダ
├── tools/      ← 執筆を助ける小さな道具（Pythonスクリプトなど）
└── notes/      ← 開発メモ。試したこと・詰まったこと・やめた理由
```

`notes/` は捨て場ではなく記録場所です。
「これ前に試してダメだったな」を思い出せるようにしておくと、遠回りが一度で済みます。

---

## 普段の作業のしかた

開発ブランチに移動してから作業します。

```bash
git checkout claude/new-dev-folder-setup-5vp1x2
```

作ったら、いつも通りコミットして push します。

```bash
git add dev/
git commit -m "dev: ○○を作りはじめた"
git push -u origin claude/new-dev-folder-setup-5vp1x2
```

この時点では main は一切変わりません。安心して壊してください。

---

## main に反映したいものだけ反映する手順

完成したツールを1つだけ main に入れたい、というときはこうします。
**ファイル単位で選べる**ので、他の書きかけを巻き込みません。

```bash
# 1. main に移動する
git checkout main

# 2. 開発ブランチから、入れたいファイルだけを取ってくる
git checkout claude/new-dev-folder-setup-5vp1x2 -- dev/tools/入れたいファイル.py

# 3. コミットして push
git commit -m "dev/tools: ○○を main に追加"
git push -u origin main

# 4. 開発ブランチに戻る
git checkout claude/new-dev-folder-setup-5vp1x2
```

フォルダごと入れたいときは、手順2のパスをフォルダにします。

```bash
git checkout claude/new-dev-folder-setup-5vp1x2 -- dev/apps/入れたいアプリ/
```

> Claude に頼む場合は「dev/tools/○○.py を main に反映して」と言えば、この手順を実行します。

---

## 迷ったときの目安

- **main に入れる** — 完成して、実際に使っていて、他のチャットにも知っていてほしいもの
  （例：`原稿チェック_余白と改行.py` は毎回の納品前チェックに使うので main にある）
- **dev/ に置いたまま** — 試作、実験、動かないもの、自分だけが使うもの

判断に困ったら dev/ に置いたままで大丈夫です。
main は「すべてのチャットが読む共有の記憶」なので、確定したものだけを置くほうが、
あとから読む自分が混乱しません。

---

## 注意

- `原稿チェック_余白と改行.py` はリポジトリ直下のまま動かしません。
  CLAUDE.md が実行パスを指定しているので、移動するとチェックが失敗します。
- `dev/` の中で作った Python の一時ファイル（`__pycache__` など）は
  `.gitignore` で除外済みなので、そのまま作業して大丈夫です。
