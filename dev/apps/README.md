# dev/apps/ — アプリ開発

1つのアプリにつき、1つのフォルダを作ります。

```
dev/apps/
└── アプリ名/
    ├── README.md   ← 何を作るのか・どう動かすのか
    └── （コード）
```

## 新しく作るとき

まずフォルダと README.md だけ作って、README に3行だけ書いておくと迷子になりません。

- **何のためのアプリか**（誰の、どんな困りごとを減らすのか）
- **今どこまでできているか**
- **どうやって動かすか**（コマンド1行）

コードより先に「何のため」を書いておくと、
しばらく放置してから戻ってきた自分が助かります🌙

## これから作りたいもの

### 自作タロットデッキを引けるアプリ（いずれ）

アニメ・タロットカードの創作シリーズが完成したら、自作デッキを引けるアプリにする。

**技術的な下地はもうある。** `dev/tools/次のカード.py` がやっている
「デッキから条件に合うカードを選ぶ」処理と、中身はほぼ同じ。

**今から準備しておくこと（あとの手間が激減する）**

1. **カード画像のファイル名を最初から決める** … `00_fool.png` `01_magician.png` の形。
   1枚描くたびにこの名前で保存する。78枚たまってからリネームするのは苦痛
2. **1か所にまとめる** … 記事ごとのフォルダに散らばると、集めるだけで一日かかる
3. **意味のテキストも同時に貯める** … 連載で書いた解説をそのまま流用できる形で残す

**完成を待たずに、大アルカナ22枚で先に公開する。** 78枚そろうのを待つと出せない。
「小アルカナは順次追加」と書いておけば足りるし、育つ様子を見せられる方がゆめらしい。

**要判断**: `記事/セルフケア/paid_大アルカナ22枚やさしい意味事典.md` に
大アルカナ22枚の意味を書いた有料記事がある。アプリで同じ内容を無料で出すと、
買ってくださった方との約束が揺らぐ。アプリには短い一言だけ載せて詳細は有料記事へ
誘導するか、アプリ用に別の切り口を書き下ろすか、公開前に決めること。
