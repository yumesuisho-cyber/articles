# dev/apps/ — アプリ開発

1つのアプリにつき、1つのフォルダを作ります。

```
dev/apps/
└── アプリ名/
    ├── README.md   ← 何を作るのか・どう動かすのか
    └── （コード）
```

## 新しく作るとき

まずフォルダと README.md だけ作って、README に3行だけ書いておくと迷子になりません。

- **何のためのアプリか**（誰の、どんな困りごとを減らすのか）
- **今どこまでできているか**
- **どうやって動かすか**（コマンド1行）

コードより先に「何のため」を書いておくと、
しばらく放置してから戻ってきた自分が助かります🌙

### ゆめの依頼窓口（依頼が増えてきたら）

公式サイトのお問い合わせフォームの裏側。お仕事の依頼を台帳で管理する。
セミナー課題1-4の要件（100点スコア・3段階振り分け・人の承認ゲート）が
そのまま流用できる形で仕様まで作ってある。

- 受信箱（相性スコアで振り分け）／審査／返信／進行中／基準とふりかえり の5タブ
- 相性スコア: 掛け算案件・納期のゆとり・世界観への理解で加点、
  煽り系・極端な短納期・内容が曖昧で減点

  いまはまだ不要（2026-08-05時点で継続案件1件）
- フォームとの自動連携はしない。メールで届いた依頼を手で書き写す台帳でよい

### 自作タロットデッキを引けるアプリ（いずれ）

アニメ・タロットカードの創作シリーズが完成したら、自作デッキを引けるアプリにする。

**技術的な下地はもうある。** `dev/tools/次のカード.py` がやっている
「デッキから条件に合うカードを選ぶ」処理と、中身はほぼ同じ。

**デッキは大アルカナ22枚で完成**（アニメ・創作シリーズとも大アルカナのみ）。
小アルカナは作らないので、「全部そろうまで出せない」問題は起きない。

**アプリの目的は「自作タロットを見てもらうこと」。** 読ませるものではないので、
添えるメッセージは短くてよい。導線も置かない方針。

**今から準備しておくこと（あとの手間が激減する）**

1. **デッキごとにフォルダを分け、中のファイル名は共通にする**

   ```
   カード画像/
   ├── deck-a/          ← デッキ1（フォルダ名は英数字）
   │   ├── 00_fool.png
   │   ├── 01_magician.png
   │   └── ...
   └── deck-b/          ← デッキ2
       ├── 00_fool.png
       └── ...
   ```

   デッキは2種類になる予定。**同じファイル名のまま置けば、アプリはフォルダを
   切り替えるだけでデッキを変えられる。** 3つ目が増えてもフォルダを足すだけ。
   ファイル名に接頭辞を付ける方式より扱いやすい。

2. **1か所にまとめる** … 記事ごとのフォルダに散らばると、集めるのに手間がかかる
3. **短い一言も同時に貯める** … カードごとに1〜2行。連載を書くときについでに書いておく

**要確認**: Pollo AIさま案件「ゆめとルナがゆく タロットの世界」のカードを、
自分のアプリに使ってよいか。継続案件なので成果物の扱いに取り決めがある可能性がある
（二次利用の可否・クレジット表記・掲載先の制限）。使えない場合はタロット工房の
デッキ1つで公開すればよく、致命的ではないが、早めに確認しておくと安心。

**有料記事との関係**: `記事/セルフケア/paid_大アルカナ22枚やさしい意味事典.md` が
同じ22枚を扱っているが、アプリに載せるのは短い一言だけなので内容は重ならない。
アプリに解説を長く書き足したくなったときだけ、扱いを考え直す。
